# Requirements Archive — v1.4 Animation Performance Optimization

**Archived:** 2026-04-23
**Milestone:** v1.4 Animation Performance Optimization
**Status:** ✅ SHIPPED

---

## Milestone Goal

Eliminate React reconciliation overhead on each frame update so the homepage terminal animation runs as smoothly as Ghostty's.

## Requirements — Final Status

### Core Rendering

- [x] **RENDER-01**: Terminal component exposes content element ref via `React.forwardRef` — ✓ Phase 7
- [x] **RENDER-02**: Terminal uses stable `key={i}` for line divs (not `key={i + line}`) — ✓ Phase 7
- [x] **RENDER-03**: AnimatedTerminal uses direct `innerHTML` patching via `contentRef` instead of `setCurrentFrame` for frame updates after initial render — ✓ Phase 8

### Lifecycle & Correctness

- [x] **LIFE-01**: AnimatedTerminal `useEffect` cleanup calls `animationManager.pause()` to cancel rAF loop on unmount — ✓ Phase 8
- [x] **LIFE-02**: AnimatedTerminal listens to `document.visibilitychange` to pause/resume on tab switch — ✓ Phase 8
- [x] **LIFE-03**: `prefers-reduced-motion` check uses a reactive `matchMedia` listener (not one-time mount check) — ✓ Phase 8

### CSS Performance

- [x] **CSS-01**: `.terminal` has `contain: strict` to isolate layout/paint from page — ✓ Phase 8
- [x] **CSS-02**: `.content` has `will-change: contents` for GPU compositor layer — ✓ Phase 8

### Accessibility

- [x] **A11Y-01**: `<Code>` element has `aria-live="off"` to prevent screen reader announcements on innerHTML updates — ✓ Phase 8

## Future Requirements

- IntersectionObserver-based pause when terminal scrolls out of viewport (defer — terminal is above the fold)
- `content-visibility: auto` on terminal container (defer — low payoff until page grows)

## Out of Scope

- New npm packages — all changes use existing React APIs and browser APIs
- Changes to animation frame content or generation pipeline — frames are correct, rendering is the issue
- Server-side rendering changes — site remains fully static
