# Milestone v1.4: Animation Performance Optimization

**Status:** ✅ SHIPPED 2026-04-23
**Phases:** 7–8
**Total Plans:** 2

## Overview

Eliminated React reconciliation overhead on each animation frame update. The homepage terminal animation now runs at full 30fps without triggering React re-renders — matching Ghostty's rendering performance. Achieved via direct `innerHTML` patching, stable DOM keys, CSS containment, and three lifecycle correctness fixes.

## Phases

**Goal**: Terminal component is ref-forwarding and uses stable keys so React never recreates DOM nodes for unchanged lines

### Phase 8: AnimatedTerminal DOM Patching & Lifecycle

**Goal**: Animation frame updates bypass React reconciliation entirely, the animation pauses correctly on tab switch and reduced-motion preference, and the terminal is GPU-composited with no screen reader noise
**Depends on**: Phase 7
**Plans**: 1 plan

Plans:

- [x] 08-01: Refactor AnimatedTerminal to direct innerHTML, fix lifecycle bugs, add CSS hints and aria-live

**Details:**

- `contentRef.current.innerHTML` direct write in AnimationManager callback — no `useState`, no React re-render per frame (RENDER-03)
- `useRef` for frame index and manager instance — stable mutable state that must not trigger re-renders
- Three lifecycle bug fixes: rAF leak on unmount (LIFE-01), `focus/blur` → `visibilitychange` (LIFE-02), one-time reduced-motion check → reactive `mql.addEventListener` (LIFE-03)
- `contain: strict` on `.terminal` (CSS-01), `will-change: contents` on `.content` (CSS-02)
- `aria-live="off"` on `<Code>` element (A11Y-01)
- Post-execution: span reduction 289→61 per frame (~79%), frame HTML 11.9KB→6.8KB

## Milestone Summary

**Key Decisions:**

- Direct innerHTML write in AnimationManager callback eliminates ~30 React re-renders/sec for ~11KB frame content
- `contain: strict` is safe on `.terminal` because explicit width/height are set via `--columns`/`--rows` CSS custom properties
- `will-change: contents` on `.content` promotes element to GPU compositor layer for innerHTML mutations
- Merge `h`/`g`/`o` span classes into single `w` class — reduces span count 289→61/frame without visual regression
- `generate-eye-frames.js` must be re-run after any `generate-frames.js` regeneration to restore `@ @` eye shapes

**Issues Resolved:**

- React re-render per frame (~30/sec for 11KB content) — fixed via direct innerHTML
- DOM node recreation on every frame change — fixed via stable `key={i}`
- Animation not pausing on tab switch — fixed via `visibilitychange` API
- Reduced-motion not reactive after mount — fixed via `mql.addEventListener`
- rAF loop leak on component unmount — fixed via `pause()` in cleanup

**Issues Deferred:**

- UAT: tab visibility pause/resume — 2 pending human test scenarios
- UAT: reactive prefers-reduced-motion toggle — pending human verification
- Quick task `260421-nya-reduce-terminal-spans` — shipped in dd8cb33, status stale

**Technical Debt Incurred:**

- `generate-eye-frames.js` must be re-run after any frame regeneration (not automated in pipeline)
- `frames.json` rebuild script not integrated into package.json scripts
