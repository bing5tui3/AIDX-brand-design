## Phase Nature

This phase is a **pure behavioral and performance refactoring**. No new UI surfaces, screens, or user-facing interactions are introduced. The visual output of the terminal animation must be **byte-for-byte identical** before and after the changes.

The design contract below documents:
1. The existing visual state that must be preserved (inherited from Phase 7 UI-SPEC, status: approved)
2. The specific CSS and accessibility attributes that change in this phase (CSS-01, CSS-02, A11Y-01)

## CSS Changes Contract (Phase 8 Specific)

These are the only CSS mutations permitted in this phase. All other CSS values are frozen.

### CSS-01: `.terminal` — add `contain: strict`

```css
.terminal {
  contain: strict;
  /* all existing properties unchanged */
}
```

- Isolates layout and paint of the terminal from the rest of the page.
- Must not alter the terminal's rendered dimensions or visual appearance.
- `contain: strict` implies `contain: size layout paint style`. The terminal already has explicit `width` and `height` set via CSS custom properties, so size containment is safe.

Source: REQUIREMENTS.md CSS-01

### CSS-02: `.content` — add `will-change: contents`

```css
.content {
  will-change: contents;
  /* all existing properties unchanged */
}
```

- Promotes the `.content` element to a GPU compositor layer.
- Applied to `.content` only — NOT to individual row `div` elements inside it.
- Must not alter scroll behavior, padding, font size, or color of the content area.

Source: REQUIREMENTS.md CSS-02

## Accessibility Changes Contract (Phase 8 Specific)

### A11Y-01: `<Code>` element — add `aria-live="off"`

The `<code>` DOM node rendered by the `Terminal` component (the element targeted by `contentRef`) must carry `aria-live="off"`.

- Prevents screen readers from announcing innerHTML updates as the animation advances frames.
- Value must be `"off"` — not `"polite"` or `"assertive"`.
- This attribute is set on the element that receives direct `innerHTML` writes (RENDER-03).

Source: REQUIREMENTS.md A11Y-01

## Interaction Contract

### What Must Not Change (Preservation Rules)

These behaviors are locked — Phase 8 must not alter them:

1. Visual frame output: each animation frame renders identically to pre-Phase-8. The innerHTML written by direct DOM patching must produce the same HTML as the previous `setCurrentFrame` + React render path.
2. Auto-scroll: when `autoScroll` is true, the `Code` element scrolls to bottom on `lines.length` change. The `contentRef` must remain functional for this behavior.
3. Platform detection: `platformStyle` state switches between `macos` and `adwaita` chrome on mount. Unchanged.
4. Scroll position tracking: `handleScroll` sets `autoScroll` false when not at bottom, true when at bottom. Unchanged.
5. Font size variants: all five `TerminalFontSize` values render correct CSS class. Unchanged.
6. Terminal dimensions: `width` and `height` are computed from CSS custom properties. `contain: strict` must not break this calculation.

### What Changes (Internal Only)

1. Frame updates: `AnimatedTerminal` writes frame HTML directly to `contentRef.current.innerHTML` instead of calling `setCurrentFrame`. No React re-render occurs per frame.
2. Unmount cleanup: `useEffect` cleanup calls `animationManager.pause()` to cancel the rAF loop. No visual change.
3. Tab visibility: `document.visibilitychange` listener pauses animation when tab is hidden, resumes when visible. No visual change.
4. Reduced-motion: `matchMedia('(prefers-reduced-motion: reduce)')` uses a reactive `change` listener — not a one-time mount check. Animation stays paused if the OS preference changes after mount. No visual change.

### Pause/Resume States

| Trigger | State | Visual Result |
|---------|-------|---------------|
| Tab hidden (`visibilitychange`) | paused | Last rendered frame frozen |
| Tab visible (`visibilitychange`) | resumed | Animation continues from last frame |
| `prefers-reduced-motion: reduce` active | paused | Last rendered frame frozen |
| `prefers-reduced-motion: reduce` removed | resumed | Animation continues |
| Component unmount | cancelled | rAF loop terminated, no console errors |

These state transitions have no visual design requirements beyond "frozen at last frame." No loading indicator, no fade, no transition animation.
